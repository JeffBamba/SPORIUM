📊 PANORAMICA GENERALE
======================

Questo report documenta l'ottimizzazione completa del sistema di logging del gioco,
unificando tutti i log nel sistema centralizzato SporiumLogger e rimuovendo i log
non controllati che causavano problemi di performance.

PROBLEMA RISOLTO:
- ⚠️ Log non controllati che scrivevano sempre su disco (File.AppendAllText)
- ⚠️ Overhead di performance con 2+ piante (gioco a scatti)
- ⚠️ Log duplicati e ridondanti fuori dal sistema centralizzato
- ⚠️ Impossibilità di controllare/disabilitare log di debug

SOLUZIONE IMPLEMENTATA:
- ✅ Estensione SporiumLogger con file logging NDJSON opzionale
- ✅ Migrazione di 8 log critici per debugging loop crescita
- ✅ Rimozione completa di ~15 log banali/ridondanti
- ✅ Sistema unificato e controllabile

RISULTATI:
- ✅ Nessuna scrittura su disco quando file logging è disabilitato (default)
- ✅ Performance migliorata: nessun overhead quando disabilitato
- ✅ Tutti i log critici salvati in memoria (history) per export successivo
- ✅ Sistema completamente controllabile tramite filtri categoria/livello

1. PROBLEMA IDENTIFICATO
=========================

1.1 SITUAZIONE INIZIALE
-----------------------
Il sistema di logging presentava due problemi principali:

**A) Log Non Controllati:**
- Metodi `LogToDebugFile()` in 3 file che scrivevano sempre su disco
- Blocchi `File.AppendAllText()` inline in 2 file
- Nessun controllo di abilitazione/disabilitazione
- Scrittura su disco anche quando non necessario

**B) Log Duplicati e Ridondanti:**
- Log granulari (WATER_CHECK, LIGHT_CHECK, FERTILIZER_CHECK) già presenti in console
- Log troppo frequenti (PhSystem, PotStateModel) non utili per debugging loop
- Log ridondanti (STATE_CHANGE già incluso in OUTPUT)

**C) Impatto Performance:**
- Con 2 piante: ~25-30 operazioni di logging/giorno
- Scritture su disco ogni giorno per ogni pianta
- Causava stuttering e lag durante il gameplay

1.2 ANALISI DETTAGLIATA
-----------------------
**File con LogToDebugFile:**
- `DayCycleController.cs`: 1 metodo + ~10 chiamate
- `GrowthPointsCalculator.cs`: 1 metodo + 4 chiamate
- `PlantConditionSystem.cs`: 1 metodo + 5 chiamate

**File con File.AppendAllText inline:**
- `PhSystem.cs`: 3 blocchi (ApplyInstantDelta, SetPh, ApplyQueuedDrifts)
- `PotStateModel.cs`: 1 blocco (SetLedSystemState)

**Log Critici Identificati (8 totali):**
1. DayCycleController:ResolveGrowthForPot:POINTS_CALCULATION
2. DayCycleController:ResolveGrowthForPot:OPTIMAL_DAYS_UPDATE
3. DayCycleController:ResolveGrowthForPot:ADVANCEMENT_CHECK
4. DayCycleController:CalculatePlantConditions:INPUT
5. DayCycleController:CalculatePlantConditions:OUTPUT
6. GrowthPointsCalculator:CalculateDailyPoints:RESULT
7. PlantConditionSystem:CalculateCondition:START
8. PlantConditionSystem:CalculateCondition:FINAL

**Log Banali Rimossi (~15 totali):**
- GrowthPointsCalculator: WATER_CHECK, LIGHT_CHECK, FERTILIZER_CHECK (3)
- PlantConditionSystem: HYDRATION, MOLD, PH (3)
- PhSystem: ApplyInstantDelta, SetPh, ApplyQueuedDrifts (3)
- PotStateModel: SetLedSystemState (1)
- DayCycleController: STATE_CHANGE, LED effects logs (5+)

2. SOLUZIONE IMPLEMENTATA
==========================

2.1 ESTENSIONE SPORIUMLOGGER
-----------------------------
**File:** `Assets/_Project/Scripts/DevTools/Logging/SporiumLogger.cs`

**Aggiunte:**
- Flag `_enableImmediateFileLogging` (default: false)
- Path `_immediateLogFilePath` per file NDJSON
- Metodo `SetImmediateFileLogging(bool enabled, string filePath = null)`
- Metodo `LogDebugWithLocation()` con supporto:
  - `location`: Identificatore punto nel codice
  - `hypothesisId`: ID ipotesi di debug (opzionale)
  - `runId`: ID run di test (opzionale)
- Metodo privato `WriteToNDJSONFile()` per scrittura formato NDJSON compatibile

**Comportamento:**
- Log sempre salvati in memoria (history) tramite `LogDebug()`
- Scrittura su file NDJSON solo se `_enableImmediateFileLogging == true`
- Formato NDJSON compatibile con LogToDebugFile esistente
- Nessun overhead quando file logging è disabilitato

**Formato NDJSON:**
```json
{
  "id": "log_...",
  "timestamp": ...,
  "location": "...",
  "message": "...",
  "data": {...},
  "level": "Debug",
  "category": "Pot",
  "sessionId": "sporium-session",
  "runId": "...",
  "hypothesisId": "..."
}
```

5. USO FUTURO
=============

5.1 COMPORTAMENTO DEFAULT
--------------------------
- File logging NDJSON è **disabilitato di default**
- Tutti i log critici sono salvati in memoria (history)
- Nessuna scrittura su disco automatica
- Performance ottimale senza overhead

5.2 ABILITARE FILE LOGGING PER DEBUGGING
-----------------------------------------
Per abilitare file logging NDJSON durante il debugging approfondito:

```csharp
// In GameManager.Start() o DayCycleController.Start()
SporiumLogger.SetImmediateFileLogging(true, @"d:\Sporae_Build_Beta\.cursor\debug.log");
```

**Quando usare:**
- Debugging approfondito dei loop crescita
- Analisi di problemi specifici con tool esterni
- Calibrazione parametri crescita

**Quando NON usare:**
- Gameplay normale (causa overhead)
- Build di produzione (disabilitato automaticamente)

5.3 CONTROLLO LOG TRAMITE FILTRI
---------------------------------
Disabilitare tutti i log debug della categoria Pot:
```csharp
SporiumLogger.SetCategoryEnabled(LogCategory.Pot, false);
```

Impostare livello minimo a Info (nasconde Debug):
```csharp
SporiumLogger.SetMinLogLevel(LogLevel.Info);
```

5.4 EXPORT LOG SU FILE
----------------------
Esportare history log su file JSON:
```csharp
SporiumLogger.ExportLogsToFile(@"path\to\export.json", includeStackTrace: false);
```

Esportare history log su file CSV:
```csharp
SporiumLogger.ExportLogsToCSV(@"path\to\export.csv");
```
