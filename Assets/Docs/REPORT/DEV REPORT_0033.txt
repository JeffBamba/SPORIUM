### **BUG-0033-001: Granularità Idratazione Troppo Grossa (20% per punto)**
**Numero**: BUG-0033-001  
**Descrizione**: Con `MaxHydration = 5`, ogni punto di idratazione valeva 20%, rendendo difficile la gestione strategica del sistema Watering ON/OFF perché si saltava facilmente sotto range o sopra range.  
**Causa Identificata**:
- `MaxHydration` era impostato a 5, quindi 1 punto = 20% (100% / 5 = 20%)
- Con incremento/decremento di 1 punto, era difficile rimanere nel range ottimale (50-75%)
- La forbice del 20% era troppo grande per una gestione precisa

**Soluzione Applicata**:
- Aumentato `MaxHydration` da 5 a 10 in `PotSystemConfig.asset` e `PotSystemConfig.cs`
- Aggiornati tutti i fallback hardcoded da `: 4`, `: 5` a `: 10` in 7 file
- Con `MaxHydration = 10`, 1 punto = 10% (100% / 10 = 10%)
- Incremento/decremento rimane 1 punto, ma ora vale 10% invece di 20%
- Migliorata granularità per gestione strategica del sistema Watering

**Test Verifica**:

- ✅ Testato decremento idratazione: 1 punto = 10% con MaxHydration=10

## 📚 **LEZIONI APPRESE**

### **Pattern e Best Practices**
1. **Configurabilità**: Rendere valori hardcoded configurabili migliora la manutenibilità e permette bilanciamento gameplay senza modificare codice
2. **Granularità Gameplay**: Valori più granulari (10% invece di 20%) migliorano l'esperienza di gioco permettendo gestione più strategica
3. **HUD Synchronization**: Metodi di refresh espliciti prevengono bug di UI non aggiornata quando config viene modificato
4. **Percentuali vs Assoluti**: Usare percentuali invece di valori assoluti rende il sistema più flessibile e adattabile
5. **Fallback Consistency**: Mantenere fallback coerenti in tutti i file previene inconsistenze quando config non è disponibile
6. **Single Source of Truth**: Un solo punto di configurazione (PotSystemConfig) garantisce coerenza in tutto il sistema

### **Errori Ricorrenti**
1. **Variabili Duplicate**: Dichiarare variabili con lo stesso nome nello stesso scope causa errori di compilazione `CS0128`
2. **Hardcoded Values**: Valori hardcoded in più file rendono difficile modificare il sistema e causano inconsistenze
3. **HUD Not Updated**: HUD non si aggiorna automaticamente quando config viene modificato in runtime
4. **Soglie Assolute**: Soglie basate su valori assoluti invece di percentuali non si adattano quando il sistema cambia

### **Pattern Adottati**
1. **Configurable Values**: Valori configurabili in ScriptableObject invece di hardcoded
2. **Refresh Methods**: Metodi espliciti per ricaricare config e aggiornare UI
3. **Percentage-Based Thresholds**: Soglie basate su percentuali invece di valori assoluti
4. **Consistent Fallbacks**: Fallback coerenti in tutti i file per gestire casi edge
5. **Helper Methods**: Metodi helper per recuperare valori configurabili (es. `GetMaxDaysForFullStress()`)
