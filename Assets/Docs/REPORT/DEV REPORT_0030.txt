### **TASK-001: Fix UI Blocking - BED e Elevator** ✅
**Codice**: BUGFIX-UI-BLOCKING-001  
**Descrizione**: Risoluzione del problema che impediva l'interazione con oggetti di gioco (BED, Elevator) a causa di elementi UI che bloccavano i raycast

**Codice**: BUGFIX-ACTIONS-MULTIPLE-001  
**Descrizione**: Risoluzione del problema che causava il consumo di tutte le azioni disponibili invece di una sola quando si eseguivano azioni Plant, Light o Water  
**Stato**: ✅ COMPLETATO  
**Evidenza Tecnica**:
- Aggiunto flag `_isProcessingSeedSelection` in `PotDetailsWidget.OnSeedSelected` per prevenire chiamate multiple
- Aggiunti flag `_isPlantingInProgress`, `_isLightingInProgress`, `_isWateringInProgress` in `PotActions` per prevenire chiamate multiple
- Aggiunto flag `_isBindingUI` in `PlantCardV2Controller` per prevenire azioni automatiche durante il binding UI
- Corretto `GameManager.TrySpendAction` per gestire correttamente `amount <= 0` (default a 1 azione)

### **BUG-0030-004: Azioni Light/Water Si Attivano Automaticamente**
**Numero**: BUG-0030-004  
**Descrizione**: Quando si piantava un seme o si entrava nella nuova HUD, le azioni Light e Water si attivavano automaticamente, consumando azioni  
**Causa Identificata**:
- `PotEvents.OnPotStateChanged` triggerava `RefreshData()` che aggiornava i rotary knobs
- L'aggiornamento dei knobs causava `OnIrrigationStateChanged` e `OnLedStateChanged` che chiamavano `DoWater()` e `DoLight()` automaticamente
**Soluzione Applicata**:
- Aggiunto flag `_isBindingUI` in `PlantCardV2Controller`
- `RefreshData()` imposta `_isBindingUI = true` all'inizio e `false` in un `finally` block
- `OnIrrigationStateChanged()` e `OnLedStateChanged()` controllano `_isBindingUI` e ritornano early se è `true`
**Test Verifica**:

- ✅ Testato entrare nella HUD con pianta esistente: Light e Water non si attivano automaticamente

### **Logica Implementata**

#### **UI Blocking Prevention**
- Tutti gli elementi UI non interattivi hanno `raycastTarget = false`
- Solo elementi che necessitano di interazione mantengono `raycastTarget = true`
- Questo permette ai click di passare attraverso agli oggetti di gioco sottostanti

#### **Action Consumption Protection**
- Flag di protezione a tre livelli:
  1. `_isProcessingSeedSelection` in `PotDetailsWidget` per prevenire chiamate multiple da UI events
  2. `_isActionInProgress` flags in `PotActions` per prevenire chiamate multiple alle azioni stesse
  3. `_isBindingUI` in `PlantCardV2Controller` per prevenire azioni automatiche durante il binding UI
- Ogni flag viene resettato tramite coroutine dopo un frame per garantire che le azioni possano essere eseguite di nuovo

#### **Rotary Knob Click Areas**
- `_clickAreaLeft` non può usare `click-area-off` come fallback per evitare conflitti

## 📚 **LEZIONI APPRESE**

### **Pattern e Best Practices**
1. **UI Raycast Management**: Gli elementi UI non interattivi devono avere `raycastTarget = false` per permettere ai click di passare attraverso agli oggetti di gioco
2. **Action Protection**: Protezione a più livelli (UI events, action logic, UI binding) per prevenire chiamate multiple
3. **Canvas Render Mode**: Per il layering corretto, i Canvas devono usare `ScreenSpaceOverlay` invece di `WorldSpace`
4. **Tooltip Implementation**: Tooltip devono essere aggiunti al root per evitare clipping, con `pickingMode.Ignore` e hide ritardato per prevenire flickering
5. **Debug Log Cleanup**: Rimuovere sempre i log temporanei di debug dopo aver risolto i bug

### **Errori Ricorrenti**
1. **UI Blocking**: Elementi UI con `raycastTarget = true` di default bloccano i click destinati agli oggetti di gioco
2. **Multiple Event Calls**: Eventi UI possono essere chiamati multiple volte nello stesso frame senza protezione
3. **Canvas Render Mode**: `WorldSpace` Canvas non rispetta il `sortingOrder` per il layering
4. **Tooltip Flickering**: Tooltip che catturano eventi mouse causano loop di show/hide

### **Pattern Adottati**
1. **Flag-Based Protection**: Flag booleani con reset tramite coroutine per prevenire chiamate multiple
2. **Root-Level Tooltip**: Tooltip aggiunti al root VisualElement per evitare clipping
3. **Delayed Hide**: Meccanismo di hide ritardato per tooltip per prevenire flickering
4. **Explicit Canvas Setup**: Impostazione esplicita di `renderMode` e `sortingOrder` per Canvas UI
