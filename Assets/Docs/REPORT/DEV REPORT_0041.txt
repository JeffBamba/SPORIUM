🐛 BUG FIXATI
=============
- **VM-BUG-003 (Ascensore apre UI in automatico e blocca il passaggio davanti alle porte)**:
  - **Sintomo:** entrando nel trigger, UI ascensore si apriva automaticamente e il player non poteva attraversare liberamente il pianerottolo.
  - **Causa:** trigger usato come “interazione” invece che come “prossimità”; input non gated; UI state non esplicito.
  - **Fix:** `openMenuOnTriggerEnter=false` (opzione) + apertura su `E`, con prompt “Press E to interact”.
  - **Evidence:** `Assets/_Project/Scripts/World/Elevator/ElevatorSystem.cs`
  - **Verifica:** ✅ conferma utente.

- **VM-BUG-004 (Frecce su/giù dell’ascensore spostano il player anche senza UI aperta)**:
  - **Sintomo:** passando davanti all’ascensore, i tasti freccia cambiavano piano/spostavano player senza interazione.
  - **Fix:** input frecce ammesso solo se `uiOpen==true`.
  - **Evidence:** `ElevatorSystem.Update()`
  - **Verifica:** ✅ conferma utente.

- **VM-BUG-005 (Animazione player resta in Idle mentre cammina)**:
  - **Sintomo:** player si muove ma animazione rimane “Idle”.
  - **Causa:** movimento via `Rigidbody2D.MovePosition` → `rb.velocity` spesso ≈ 0; transizioni update/fixed causavano sampling inconsistente; clip non in loop.
  - **Fix:**
    - `PlayerAnimator` usa delta-position per rilevare movimento + hold-time anti-flicker.
    - `Idle.anim` e `Walk.anim` con Loop Time ON.
  - **Evidence:**
    - `Assets/_Project/Scripts/Player/PlayerAnimator.cs`
    - `Assets/_Project/Animations/Player/Idle.anim`
    - `Assets/_Project/Animations/Player/Walk.anim`
  - **Verifica:** ✅ conferma utente.

- **VM-BUG-006 (UI ascensore resta attiva dopo teleport)**:
  - **Sintomo:** dopo arrivare a un floor, la UI piani rimaneva aperta e “bloccava” il flow di uscita.
  - **Fix:** chiusura UI a fine `TeleportPlayer`.
  - **Evidence:** `ElevatorSystem.TeleportPlayer()` → `ShowFloorOptions(false)`
  - **Verifica:** ✅ conferma utente.

- **VM-BUG-007 (Snap/teleport al primo input dopo arrivo da ascensore, soprattutto su +1)**:
  - **Sintomo:** dopo animazione ascensore, al primo WASD/click il player “scatta” verso un punto vicino o verso Seed Storage.
  - **Cause principali:**
    - mismatch tra `Transform.position` e `Rigidbody2D.position` / UV interna del mover 2.5D
    - scelta WalkArea sbagliata quando bounds si sovrappongono (punto contenuto in più aree)
    - collider non-trigger in zona arrivo (es. handler di deselect) che interferiva con il primo step
  - **Fix:**
    - Teleport sempre via `PlayerPerspectiveMover2D.TeleportToWorld(..., pickAreaByPoint:true)` (sincronizza rb + UV)
    - `FindAreaByWorldPoint()` sceglie l’area con errore minimo di proiezione
    - guard su `OnTriggerEnter2D` che rifiuta switch area con errore alto
    - `DeselectHandler` forza `Collider2D.isTrigger=true` (opzionale via toggle)
  - **Evidence:**
    - `Assets/_Project/Scripts/World/Elevator/ElevatorSystem.cs`
    - `Assets/_Project/Scripts/Player/PlayerPerspectiveMover2D.cs`
    - `Assets/_Project/Scripts/DeselectHandler.cs`
  - **Verifica:** ✅ conferma utente (“FUNZIONA MOLTO BENE ORA!”).

- **VM-BUG-008 (Velocità incoerente tra floor con trapezi più grandi/piccoli)**:
  - **Sintomo:** a parità di `uvSpeed`, su alcuni floor il player andava “sotto steroidi”, su altri lento.
  - **Causa:** WASD in UV-space: stessa delta UV corrisponde a metri diversi a seconda del trapezio.
  - **Fix:** modalità “constant world speed” per WASD (stima locale clamp-safe con differenze centrali).
  - **Evidence:** `Assets/_Project/Scripts/Player/PlayerPerspectiveMover2D.cs` (`useConstantWorldSpeedForWASD`, `wasdWorldSpeed`)
  - **Verifica:** ✅ conferma utente (issue fixed).

📚 LEZIONI APPRESE
=================
- **UV-speed ≠ world-speed**: in un trapezio 2.5D la metrica world varia con la forma; per avere “feel” consistente serve conversione in world-space o compensazione locale.
- **Bounds sovrapposti**: scegliere “la prima area che contiene il punto” è fragile → meglio scegliere per errore minimo di proiezione.
- **Teleport + Rigidbody2D**: mai settare solo `Transform.position` se il mover usa `Rigidbody2D.MovePosition`; serve una API di teleport che riallinei stato interno.
