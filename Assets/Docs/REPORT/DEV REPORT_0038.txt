🐛 BUG FIXATI
=============

BUG-0038-001 — PlantCardV2 non mostra Mold Risk Level impostato da debug console
- **Descrizione:** Quando la debug console POT impostava `MoldRiskLevel = 2` su un pot, PlantCardV2 continuava a mostrare `0` (None) invece del valore corretto.
- **Causa:** Il binding in `PlantCardV2DataBinder.BindVitalParameters()` utilizzava `MoldSystem.GetMoldRiskLevel()` che ricalcolava il livello basandosi su `CalculateMoldRisk()` (che calcola basandosi su `DaysOverwateringConsecutive`), ignorando completamente `state.MoldRiskLevel` quando impostato manualmente.
- **Soluzione:** Modificato il binding per usare direttamente `state.MoldRiskLevel` invece di chiamare `GetMoldRiskLevel()`. Questo rispetta i valori impostati manualmente mantenendo la compatibilità con i valori calcolati automaticamente.
- **Verifica:** 
  - ✅ Impostato `MoldRiskLevel = 2` dalla debug console POT
  - ✅ PlantCardV2 mostra correttamente "Severe" (Level 2)
  - ✅ Il valore persiste anche dopo chiusura/riapertura di PlantCardV2
  - ✅ Compatibilità mantenuta con valori calcolati automaticamente dal `DayCycleController`

BUG-0038-002 — UIAdditiveSelector mostra "NO ADDITIVES" nonostante inventario
- **Descrizione:** Additive Selector mostrava "NO ADDITIVES" anche quando l'inventario conteneva additivi.
- **Causa:** `GameManager` stava ancora seminando il vecchio `Items.SprayAntifungal` (`STR-004`) nell'inventario, mentre `AdditiveSelectorController` cercava solo `Items.AdditiveBasic` (`STR-004-Basic`) e `Items.AdditiveAcid` (`STR-004-Acid`).
- **Soluzione:** 
  - Modificato `AdditiveSelectorController.GetQty()` per controllare anche `Items.SprayAntifungal` se `typeId` è `Items.AdditiveBasic`, trattando lo spray legacy come Basic Additive per retrocompatibilità
  - Modificato `GameManager.cs` per seminare `Items.AdditiveBasic` e `Items.AdditiveAcid` direttamente, rimuovendo il seeding di `Items.SprayAntifungal` per nuovi game starts
- **Verifica:**
  - ✅ Additive Selector mostra correttamente Basic e Acid additivi
  - ✅ Retrocompatibilità mantenuta: spray legacy viene mostrato come Basic

- **Pattern Consistency:** Seguire esattamente il pattern di `UIFertilizerSelector` / `UISeedSelector` per `UIAdditiveSelector` garantisce coerenza e manutenibilità. L'uso di ServiceContainer late binding e eventi standardizzati facilita l'integrazione.

- **Foundation UI Toolkit:** L'uso della Foundation UI Toolkit (`SP-Foundation.uss`, `SP-Panel-Base.uss`) garantisce coerenza estetica e riduce duplicazione di codice. Il target estetico identico a `SeedInventoryMenu` mantiene l'esperienza utente coerente nel flow POT OPS.

- **Event-Driven Updates:** L'uso di eventi (`OnPhChanged`, `OnInventoryChanged`) per aggiornare HUD automaticamente elimina la necessità di modifiche manuali ai componenti HUD esistenti.

- **Separazione Responsabilità:** `MoldSystem` gestisce la logica di muffe, `PotActions` gestisce le azioni del giocatore, `UIAdditiveSelector` gestisce la selezione. Questa separazione facilita test e manutenzione.

**Fix Mold Risk Level Display:**

- **Binding UI vs Calcolo Sistema:** Quando un valore può essere impostato manualmente (es. debug console) o calcolato automaticamente (es. DayCycle), il binding UI deve leggere direttamente il valore dallo stato invece di chiamare il metodo di calcolo. Il metodo di calcolo è utile per il sistema di gioco, ma non per la visualizzazione quando il valore può essere sovrascritto manualmente.

- **Debug Mode Workflow:** L'uso di log di debug sistematici (entry/exit/values) è essenziale per identificare problemi di binding/calcolo. I log hanno rivelato immediatamente che `GetMoldRiskLevel()` ignorava `state.MoldRiskLevel`.

- **Separazione Responsabilità:** `MoldSystem.GetMoldRiskLevel()` è progettato per calcolare il livello basandosi su condizioni di gioco (overwatering). Quando il valore viene impostato manualmente, il binding deve leggere direttamente dallo stato, non ricalcolare.

- **Retrocompatibilità:** Il fix mantiene la compatibilità con il sistema esistente: il `DayCycleController` continua a calcolare e aggiornare `MoldRiskLevel` automaticamente, e PlantCardV2 mostra correttamente questi valori.
