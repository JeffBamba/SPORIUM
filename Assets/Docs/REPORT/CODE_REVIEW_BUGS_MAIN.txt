**BUG #1: Inventory.Add() - Null Reference Non Gestito** ✅ **FIXATO**
**File:** `Assets/_Project/Scripts/Core/ItemsSystem/Inventory.cs`
**Linea:** 26-40
**Severità:** 🔴 CRITICA

**Descrizione:**
Se `ItemFabric.CreateItemByType()` restituisce null, il codice logga un errore ma continua l'esecuzione, causando NullReferenceException.

**Codice Problematico:**
```csharp
public void Add(Item item)
{
    if (item == null)
        Debug.LogError("[Inventory.Add] Item is null");  // ❌ Log ma continua
    
    if (_slots.TryGetValue(item.TypeId, out InventorySlot existingItem))  // ❌ Crash se item è null
        existingItem.AddItem(item);
    // ...
}
```

**Problema:**
- Se `item` è null, il controllo logga ma non fa return
- La riga successiva accede a `item.TypeId` causando NullReferenceException
- Può verificarsi se ItemFabric.CreateItemByType() fallisce

**Fix Applicato:**
```csharp
public void Add(Item item)
{
    if (item == null)
    {
        Debug.LogError("[Inventory.Add] Item is null");
        return;  // ✅ Esce subito per evitare NullReferenceException
    }
    
    if (_slots.TryGetValue(item.TypeId, out InventorySlot existingItem))
        existingItem.AddItem(item);
    // ...
}
```

**Status:** ✅ **FIXATO** - Aggiunto return dopo controllo null per prevenire crash
**Data Fix:** 2025-01-XX

**BUG #2: PotActions.Awake() - Null Reference su _playerInventory** ✅ **FIXATO**
**File:** `Assets/_Project/Scripts/Dome/PotActions.cs`
**Linea:** 84-85
**Severità:** 🔴 CRITICA

**Descrizione:**
Se `FindObjectOfType<GameManager>()` restituisce null, `_playerInventory` sarà null causando crash in tutti i metodi che lo usano.

**Codice Problematico:**
```csharp
_gameManager = FindObjectOfType<GameManager>();
_playerInventory = _gameManager.PlayerInventory;  // ❌ NullReferenceException se _gameManager è null
```

**Problema:**
- Nessun controllo null dopo FindObjectOfType
- Se GameManager non esiste ancora (timing issue), crash immediato
- Tutti i metodi che usano _playerInventory crasheranno

**Fix Suggerito:**
```csharp
_gameManager = FindObjectOfType<GameManager>();
if (_gameManager == null)
{
    Debug.LogError("[PotActions] GameManager non trovato! Tentativo di recupero ritardato...");
    StartCoroutine(WaitForGameManager());
    return;
}
_playerInventory = _gameManager.PlayerInventory;
```

**Status:** ✅ **FIXATO** - Aggiunto controllo null e coroutine WaitForGameManager() per late binding
**Data Fix:** 2025-01-XX

**BUG #6: EconomySystem.Add() - Logica Incompleta** ✅ **FIXATO**
**File:** `Assets/_Project/Scripts/Core/EconomySystem.cs`
**Linea:** 27-44
**Severità:** ⚠️ ALTA

**Descrizione:**
Se `CurrentCRY` è già al `MaxCRY`, il metodo restituisce `false` anche se l'operazione è tecnicamente "riuscita" (non ha aggiunto perché già al max).

**Codice Problematico:**
```csharp
public bool Add(int amount)
{
    if (amount <= 0) 
        return false;
    
    int newAmount = Math.Min(CurrentCRY + amount, MaxCRY);
    if (newAmount != CurrentCRY)  // ❌ Se già al max, newAmount == CurrentCRY, ritorna false
    {
        CurrentCRY = newAmount;
        OnCRYChanged?.Invoke(CurrentCRY);
        return true;
    }
    
    return false;  // ❌ Restituisce false anche se l'operazione è "valida" (già al max)
}
```

**Problema:**
- Se il giocatore è già al max CRY, `Add()` restituisce false
- Questo può confondere i sistemi che chiamano questo metodo
- L'operazione è tecnicamente "riuscita" (non c'è errore, è solo già al max)

**Status:** ✅ **FIXATO** - Restituisce true se già al max (operazione valida)
**Data Fix:** 2025-01-XX

**BUG #8: EventSystem - Potenziale Race Condition** ✅ **FIXATO**
**File:** `Assets/_Project/Scripts/Core/EventSystem.cs`
**Linea:** 215-280
**Severità:** ⚠️ ALTA

**Descrizione:**
La coda eventi può crescere indefinitamente se eventi vengono emessi più velocemente di quanto vengono processati, causando memory leak.

**Codice Problematico:**
```csharp
if (_isProcessingEvents)
{
    if (_eventQueue.Count < maxEventQueueSize)  // ⚠️ Se coda piena, evento perso silenziosamente
    {
        _eventQueue.Enqueue(new EventData(eventName, parameters, false));
    }
    return;  // ❌ Evento perso senza notifica
}
```

**Problema:**
- Se la coda è piena, l'evento viene perso senza avviso
- Nessun meccanismo di backpressure
- Memory leak se eventi vengono emessi in loop

**Status:** ✅ **FIXATO** - Aggiunto warning quando coda piena invece di perdere evento silenziosamente
