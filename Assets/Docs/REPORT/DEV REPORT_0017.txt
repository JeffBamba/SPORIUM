**BUG 1: Progresso WATER mostra 33% invece di 25%**
- **Numero:** BUG-0017-001
- **Descrizione:** Dopo aver modificato la configurazione, il progresso mostrava ancora 33% invece di 25%
- **Causa:** 
  - Valori hardcoded nei widget UI (2/3 invece di usare _growthConfig)
  - File di configurazione multipli non sincronizzati
  - Caching degli asset Resources
- **Soluzione:** 
  - Aggiornati tutti i file PlantGrowthConfig.asset (4 file totali)
  - Sostituiti valori hardcoded con riferimenti dinamici a _growthConfig
  - Aggiunti log di debug per tracciare valori usati

**BUG 2: Schermata Nera e Crash dopo Reimport All**
- **Numero:** BUG-0017-002
- **Descrizione:** Dopo Reimport All, quando si mette in Play, la camera rimane nera e il gioco non si avvia
- **Causa:** 
  - `Resources.UnloadAsset()` chiamato su asset ancora in uso causava crash
  - `ServiceContainer.Instance` poteva essere null durante inizializzazione
  - Servizi null registrati senza controlli causavano crash successivi
  - `ServiceContainer.Get()` lanciava eccezioni KeyNotFound invece di gestire gracefully
- **Soluzione:** 
  - Rimosso `Resources.UnloadAsset()` da LoadGrowthConfig()
  - Aggiunti controlli null in GamePlayInstaller prima di registrare servizi
  - Aggiunti controlli null in ServiceContainer.Register() per prevenire registrazione null
  - Aggiunto controllo null e warning in ServiceContainer.Get() invece di eccezione
  - Aggiunto warning se UINotification non assegnato invece di crash silenzioso
- **Test:** ✅ Gioco si avvia correttamente dopo Reimport All, nessuna schermata nera

💡 LEZIONI APPRESE
==================

**Best Practices:**
1. **Non usare Resources.UnloadAsset() su asset ancora in uso** - Causa crash silenziosi difficili da debuggare
2. **Sempre controllare null prima di registrare servizi** - Previene crash durante inizializzazione
3. **Evitare valori hardcoded** - Usare sempre riferimenti a ScriptableObject per configurazioni
4. **Sincronizzare tutti i file di configurazione** - Evitare discrepanze tra file multipli
5. **Aggiungere log informativi invece di crash silenziosi** - Facilita debugging

**Pattern Adottati:**
- Controlli null robusti prima di operazioni critiche
- Warning informativi invece di crash per servizi mancanti
- Log di debug per tracciare calcoli importanti
- Gestione graceful di errori invece di eccezioni non gestite

**Errori Ricorrenti:**
- Tentativo di forzare ricaricamento asset Resources (causa crash)
- Valori hardcoded invece di riferimenti dinamici
- Mancanza di controlli null durante inizializzazione
